# Как помочь проекту

Спасибо за интерес. Проект маленький, правила тоже короткие.

English: [CONTRIBUTING.md](CONTRIBUTING.md).

## Главное правило

**Три реализации в каждом семействе обязаны оставаться эквивалентными.**

- **Генерируемый текст** (новый или изменённый шаблон, порядок записи, каталоги с
  `.gitkeep`, строки `.gitignore`, номер релиза) правится **один раз**: в
  `templates/<семейство>/*.tpl`, `templates/<семейство>/layout.json` или `VERSION`.
  Затем запустите `python3 tools/sync-templates.py` — он перепишет сгенерированный блок
  во всех шести скриптах. CI запускает его с `--check` и падает, если скрипт устарел;
  сгенерированный блок руками не правят.
- **Логика** (новый флаг, новое правило записи) по-прежнему вносится
  **одновременно во все три скрипта затронутого семейства**.

У шаблонов суффикс `.tpl`, чтобы агенты, работающие с этим репозиторием, не приняли
`templates/ai/AGENTS.md.tpl` за инструкции самого репозитория.

AI-семейство:

- `init-ai-tooling.sh`
- `init_ai_tooling.py`
- `init-ai-tooling.ps1`

Repo-bootstrap семейство (то же правило):

- `init-repo-bootstrap.sh`
- `init_repo_bootstrap.py`
- `init-repo-bootstrap.ps1`

CI сравнивает деревья побайтово (AI, repo и `--also-repo`) и упадёт при расхождении.

При бампе релиза измените корневой файл `VERSION` и запустите
`python3 tools/sync-templates.py` (он обновит константу и заголовок во всех шести
скриптах), затем `CHANGELOG.md` + `CHANGELOG.ru.md` и badge версии в обоих README.

Проверить локально до пуша:

```bash
mkdir -p /tmp/a /tmp/b
(cd /tmp/a && ./init-ai-tooling.sh --name demo --desc "Test")
(cd /tmp/b && python3 ./init_ai_tooling.py --name demo --desc "Test")
python3 tests/compare-trees.py /tmp/a /tmp/b     # ожидается "Trees are identical"

mkdir -p /tmp/ra /tmp/rb
(cd /tmp/ra && ./init-repo-bootstrap.sh --name demo --desc "Test" --profile full)
(cd /tmp/rb && python3 ./init_repo_bootstrap.py --name demo --desc "Test" --profile full)
python3 tests/compare-trees.py /tmp/ra /tmp/rb
```

Если установлен PowerShell 7 (`pwsh`), скрипты `.ps1` запускаются и на macOS/Linux;
Windows PowerShell 5.1 дополнительно проверяет CI на `windows-latest`.

## Грабли, на которые уже наступали

Эти вещи легко сломать заново, поэтому они вынесены отдельно.

**PowerShell: только литеральные here-string.** Шаблоны объявляются как `@'…'@`, а не
`@"…"@`. В раскрываемой here-string обратный апостроф — escape-символ: markdown-бэктики
из шаблонов исчезнут, а `` `a `` превратится в BEL (0x07) прямо посреди файла.

**PowerShell: файл обязан быть в UTF-8 с BOM.** Без BOM Windows PowerShell 5.1 читает
`.ps1` в ANSI-кодовой странице; не-ASCII байты могут декодироваться в типографские
кавычки `“` `”`, а PowerShell считает их разделителями строк — файл перестаёт
парситься целиком. CI проверяет наличие BOM отдельным шагом.

**PowerShell: here-string не отдаёт завершающий перевод строки** перед закрывающим `'@`.
За это отвечает `Write-Utf8LfFile` — она дописывает `\n` непустому содержимому.

**PowerShell: `.NET` не знает про `Set-Location`.** `[System.IO.*]` резолвит относительные
пути через `[Environment]::CurrentDirectory`, который не синхронизирован с расположением
PowerShell. Скрипт синхронизирует его в начале и отказывается работать вне
FileSystem-провайдера. Не убирайте эти проверки.

**Подстановка в JSON.** Имя проекта попадает в `.claude/settings.json`, поэтому для него
есть отдельный плейсхолдер `__NAME_JSON__` с экранированием `\` и `"`. Обычный `__NAME__`
внутрь JSON подставлять нельзя.

**PowerShell: `-replace` — это регулярка.** Правая часть трактует `$1`, `$&`, `$$` как
подстановки, поэтому для подстановки значений используется `.Replace()`.

**Вывод — всегда LF.** На всех ОС, включая Windows. `tests/compare-trees.py` намеренно
не нормализует переводы строк, чтобы CRLF считался ошибкой.

## Стиль

- Скрипты самодостаточны: шаблоны встроены (генерируются из `templates/`), внешних
  зависимостей нет — любой скрипт можно скопировать отдельно.
- Идемпотентность: без `--force` / `-Force` существующие файлы не трогаются.
- Ничего не удалять. Скрипт только создаёт файлы и дописывает строки в `.gitignore`.
- `bash` проходит `shellcheck`, `.ps1` — `PSScriptAnalyzer` без ошибок уровня Error.
- Комментарии и сообщения — на **английском**, чтобы не смешивать языки внутри файла.

## Pull request

1. Ветка от `main`.
2. Правка `templates/` и запуск `tools/sync-templates.py` либо изменение логики во всех
   трёх скриптах; затем локальная проверка эквивалентности.
3. Если поведение изменилось — обновите оба README (`README.md` и `README.ru.md`).
4. В описании PR: что меняется и зачем.

Зелёный CI обязателен для мерджа.
