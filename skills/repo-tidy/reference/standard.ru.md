# Традиция раскладки репозитория

English: [standard.md](standard.md).

Правила документации и AI-раскладки для любого проекта. Раскладку по этой традиции генерирует
`ai-tooling-starter-kit`; `scripts/check_layout.py` сверяет с ней репозиторий.

## Принципы

1. **Один источник истины — `AGENTS.md`.** Остальные файлы инструментов — тонкие редиректы:
   меняется проект → правится `AGENTS.md`, специфика инструмента — в файле инструмента.
2. **Один корень документации — `docs/`** с картой `docs/README.md`.
3. **Статус честный.** «Ready», «Done», счётчики тестов и «следующий приоритет» сверены с кодом
   и прогоном. Устаревший документ хуже отсутствующего.
4. **Артефакт — снимок на дату.** Задним числом не переписывается; актуальное — в `AGENTS.md` §4.
5. **Ссылка разрешима.** Относительные ссылки живые, номер ADR — с префиксом репозитория.
6. **Секреты закрыты дважды:** от коммита (`.gitignore`) и от чтения агентом (`.claude/settings.json`).
7. **Язык служебных файлов — язык проекта.** Публичный проект может
   вести служебные файлы на английском с переводами `*.ru.md`; пары синхронны по смыслу, а
   заголовки разделов `AGENTS.md` — английские с той же нумерацией (`## 1. Project` …).

## Раскладка

```text
AGENTS.md                  источник истины (разделы ниже)
CLAUDE.md GEMINI.md        импорт @AGENTS.md (или тонкий редирект) + специфика инструмента
.cursorignore              (.cursorrules — только если проект его держит; Cursor читает AGENTS.md сам)
PERPLEXITY.md              по потребности: вставляемый бриф Роль / Для чего / Границы / Формат выдачи
README.md                  точка входа для человека: что это, быстрый старт, структура
CHANGELOG.md               раздел «## Unreleased»
LICENSE SECURITY.md        правообладатель — реальный владелец проекта
.gitignore .gitattributes .editorconfig
.ai/README.md              карта инструментов; ниже пометки — специфика и индекс артефактов
.ai/artifacts/             артефакты всех инструментов  YYYY-MM-DD-тема.md
.claude/settings.json      allow ["Read","Edit"] + deny-базовый список
.claude/{agents,commands}/
.cursor/rules/000-project.mdc 010-safety.mdc
.<инструмент>/artifacts/   необязательно: только если проект разделяет артефакты по инструментам
.agents/skills/            переносимые навыки агентов
docs/README.md             карта документации
docs/adr/README.md         реестр ADR с таблицей префиксов
docs/adr/ПРЕФИКС-NNNN-тема.md
docs/runbooks/             процедуры
docs/<прочее>/             architecture/, prd/, test-plans/, reviews/, releases/ … по потребности
```

Пустой каталог держится файлом `.gitkeep`.

## `AGENTS.md`

Первая строка — `# AGENTS.md — <репозиторий>`. Обязательные разделы по порядку:

1. `## 1. Проект` — что и зачем, кто пользователи, ключевые требования.
2. `## 2. Стек`
3. `## 3. Структура` — таблица «каталог → назначение»; каждый корневой каталог в ней есть.
4. `## 4. Статус / текущий приоритет` — что сделано, счётчик тестов (из прогона), **что блокирует**
   следующий шаг и сам следующий шаг.
5. `## 5. Как вносить изменения (агент)`
6. `## 6. Безопасность (NEVER)`
7. `## 7. Definition of Done`
8. `## Раскладка инструментов` — начинается строкой
   ``Артефакты — в `.ai/artifacts/` (кросс) и `.<инструмент>/artifacts/`. Детали — `.ai/README.md`.``
   (без отдельных папок инструментов — ``Артефакты — в `.ai/artifacts/`. Детали — `.ai/README.md`.``;
   английский вариант — `## Tool layout`).

В англоязычных репозиториях заголовки — `## 1. Project` … `## Tool layout`; сверщик принимает
оба варианта. Дополнительные разделы допустимы между обязательными; уточнение после названия — тоже.

## Редиректы

`CLAUDE.md`: строка импорта `@AGENTS.md` (Claude Code загружает файл сам; `GEMINI.md` —
`@./AGENTS.md` для Gemini CLI) или прозаический редирект «Источник истины — `AGENTS.md`.
Прочитай его первым.» — импорт надёжнее, редирект зависит от того, откроет ли модель файл.
Дальше — только Claude-специфика (каталоги `.claude/`, settings). Не дублировать правила проекта. Больше ~40 строк — признак,
что общее утекло из `AGENTS.md`.

## `.ai/README.md`

Общая часть — таблица «инструмент → файл → артефакты» и правило «меняется проект → правь
`AGENTS.md`». Специфика репозитория — ниже строки-пометки (`<!-- Ниже — специфика репозитория. -->`
по-русски, `<!-- Below: repository-specific notes … -->` по-английски):
индекс артефактов, исполняемые конвенции (`/команды`, субагенты).

## Артефакты

- Имя `YYYY-MM-DD-тема.md` (каталог с вложениями — `YYYY-MM-DD-тема/`).
- Куда: по умолчанию все — в `.ai/artifacts/`. Отдельные `.<инструмент>/artifacts/` — только
  если проект их разделяет; тогда результат одного инструмента — туда.
- Что: план, ресёрч, аудит, совет (council), протокол пилота — всё, что переживает сессию.
- Снимок не правится по содержанию. Допустима механическая починка ссылок при переносе файлов.
- Указатель «актуальный статус» ведёт в `AGENTS.md` §4, а не на датированный артефакт.

## ADR

- Каталог `docs/adr/`, имя `ПРЕФИКС-NNNN-тема.md` (префикс — короткое имя репозитория
  заглавными: `API-`, `WEB-`; тема — латиницей через дефис).
- Ссылка в тексте, коде, комментариях — `ADR API-0001`. Голый `ADR-001` запрещён: номер без
  префикса неразрешим, как только у соседа появится свой «ADR-001».
- Реестр `docs/adr/README.md`: таблица префиксов (строка своего — «(этот)»), правила, таблица
  «ADR | Статус | Тема».
- Нумерация историческая; отменённый — `Superseded by ПРЕФИКС-NNNN`, не удаляется.
- Шапка: `Статус | Дата | Контекст | Связано`; разделы: Контекст → Варианты → Решение → Последствия.

## Документы

- Шапка — таблица `Статус | Дата | Связано`. Статус отражает реальность: `Draft`, `Blocked`
  (с причиной), `Ready`, `Accepted`, `Superseded`.
- Runbook: когда применять, предусловия и доступы, нумерованные идемпотентные шаги, abort-критерии,
  откат, эскалация.
- Требования (SRS/PRD) — отдельным документом, только если они реально написаны. Не создавать
  пустой «SRS»-индекс ради галочки: карта в `docs/README.md` честнее.
- Ревью и аудиты — датированными артефактами (или `docs/reviews/YYYY-MM-DD-тема.md`, если они
  часть продуктовой документации).

## `.claude/settings.json`

```json
{
  "permissions": {
    "allow": ["Read", "Edit"],
    "deny": ["Read(.env)", "Read(.env.*)", "Read(**/*.pem)", "Read(**/*.key)",
             "Read(**/.ssh/**)", "Read(**/.aws/**)", "Read(**/.kube/**)",
             "Bash(rm -rf:*)", "Bash(git push --force:*)"]
  }
}
```

Плюс секреты конкретного репозитория (`Read(config.yaml)`, `Read(deploy/x/compose.env)` …).
Голое имя действует на любой глубине; расширение на любой глубине — `**/*.pem`. Запреты — в
коммитимом файле, не в `settings.local.json`: иначе в свежем клоне их нет.

## `.gitignore`

Минимум: `.env`, `.env.*` + `!.env.example`, `.DS_Store`, `.claude/settings.local.json`,
`.claude/worktrees/`, `_to_delete/`, кэши языка. Если рядом лежит `config.example`/`*.example` —
закрыт и рабочий файл.

## Git-гигиена

- Перенос — только `git mv` (история и `git log --follow` сохраняются).
- Под git нет мусора: `.DS_Store`, `__pycache__`, `*.egg-info`, `.pytest_cache`, `node_modules`, `.env`.
- `.gitattributes` закрепляет LF (`* text=auto eol=lf`, бинарники — `binary`); после его
  изменения — `git add --renormalize .`.
- Коммиты — Conventional Commits (`docs:`, `chore:`, `fix:` …), одно логическое изменение на коммит.
